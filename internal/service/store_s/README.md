## “我的保存”页面交互与展示逻辑

“我的保存”页面用于集中管理用户创建并持久化的形式语言学习资源，按内容类型划分为 **文法（Grammar）**、**自动机（Automaton）** 和 **正则表达式（Regular Expression）** 三类。考虑到用户实际保存数量通常不超过 100 条，系统采用 **前端全量加载 + 本地分页** 的轻量级交互模型，在保证性能的同时提供流畅的跳页与详情查看体验。

### 1. 类型切换机制
- 页面顶部提供三个横向排列的**类型标签**：“文法”、“自动机”、“正则表达式”。
- 用户首次点击某一标签时，前端调用对应 `FindXXX` 接口（如 `FindGrammars`），**一次性拉取该类型下用户的所有记录**（通过设置足够大的 `limit`，如 200，确保覆盖全部数据）。
- 后续再次切换至该标签时，**直接使用已缓存的全量数据**，避免重复请求。
- 默认激活“文法”标签。

> 📌 注：虽然后端接口基于游标分页设计（返回 `has_more` 与 `next_cursor`），但前端在小数据场景下仅发起一次请求即可获取完整列表。

### 2. 记录展示形式
- 每条记录以**可交互行式标签**呈现（非静态文本），具备点击响应能力。
- 每行左侧显示**页内顺序编号**（如 1, 2, 3…），该编号为当前分页内的视觉序号，**不反映数据库 ID 或全局顺序**。
- 行内展示字段包括：
  - `name`：用户为该资源指定的名称；
  - `created_at`：创建时间（格式化为易读字符串）。
- 每行最右侧固定显示 **“删除”按钮（图标为 “×”）**，点击后弹出确认对话框，确认后调用对应删除接口，并**在前端本地移除该记录**，同时自动调整分页状态（如最后一页变空则跳回上一页）。

### 3. 内容展开机制
- 用户点击任意记录行时，该行下方**动态展开一个详情面板**，展示该资源的完整结构化内容：
  - **文法**：`GrammarItem.grammar` 字段的 JSON 表示；
  - **自动机**：`AutomatonItem.automaton` 字段的 JSON 表示；
  - **正则表达式**：`RegexItem.pattern` 字段的 JSON 表示。
- 再次点击同一行可收起详情，**支持多行同时展开**。
- 展开/收起状态由前端维护（基于记录的 `id`），切换标签或翻页后状态自动重置。

### 4. 分页与数据存储策略
- **数据加载**：每种资源类型首次访问时，前端发起一次 `FindXXX` 请求，获取该用户**全部记录**（因总量 ≤100，网络与内存开销可忽略）。
- **前端存储**：为三种类型分别维护独立的状态对象，包含：
  - `allItems`：该类型全量记录数组（类型为 `GrammarItem[]` / `AutomatonItem[]` / `RegexItem[]`）；
  - `currentPage`：当前页码（从 1 开始）；
  - `pageSize`：每页显示条数（默认 10）；
  - `expandedIds`：当前展开记录的 ID 集合（`Set<number>`）。
- **分页计算**：前端根据 `allItems`、`currentPage` 和 `pageSize` 动态切片生成当前页数据，并计算总页数。
- **分页组件**：右下角展示标准页码控件（如 `[1] [2] [3] … [5]`），**支持任意跳页**，无“仅下一页”限制。
- **空状态处理**：若某类型无数据，展示提示语：“暂无保存内容”。

### 💡 设计优势说明

| 优势 | 说明 |
|------|------|
| **极致简洁的交互** | 全量加载后所有操作（跳页、展开、删除）均为本地响应，无网络延迟 |
| **符合用户直觉** | 支持传统页码跳转，避免游标分页的“只能顺序翻页”限制 |
| **低开发复杂度** | 无需管理游标映射、多页缓存、ID 追踪等复杂状态 |
| **资源隔离清晰** | 三类数据状态完全解耦，切换标签无干扰 |
| **未来可扩展** | 若未来用户数据显著增长（>500），可平滑迁移至游标分页模式 |
